# Codex Buddy 0.4.8

适配 FoloToy AI Passport ESP32-C3（8MB Flash、240×320 ST7789P3）。
使用官方 BSP，替换出厂演示入口。当前采用石墨色面框、大圆角青色双眼，
电量和任务信息单独展示。
可选用 BLE 蓝牙；不使用麦克风、Wi-Fi 或云端 API。

## 0.4.8 — 可选实时输入字幕

开机及从零音量恢复时，默认音量现为 10%，仍支持手动调节。

## 0.4.7 — USB 与 BLE 蓝牙兼容

同一固件支持 USB 与 BLE（NimBLE、一个外设连接），共用以换行结尾的 v1 JSON
协议。保留现有表情、按键和 19 种音效，状态栏标记 USB/BLE。有效 USB 数据
在最后一次到达后的五秒内优先，超时后 BLE 可接管。两种连接独立组帧和排队，
超长或含 NUL 的行丢弃至下一个换行；蓝牙断开清除残留片段。蓝牙回复交由
蓝牙线程发送，并绑定连接代次，避免重连后收到旧连接的回复。

蓝牙名称 `CodexBuddy`，服务 UUID `6e400001-b5a3-f393-e0a9-e50e24dcca9e`；
RX 写入 `6e400002-b5a3-f393-e0a9-e50e24dcca9e`，TX 通知
`6e400003-b5a3-f393-e0a9-e50e24dcca9e`。双向支持 20 字节分片。
正常返回 `buddy_ack`；USB 优先期间返回 `buddy_busy`。电脑端自动重连，
检查序号匹配的确认。只发送已有任务元数据，不发送提问或回答。
这是不配对的本地状态服务，不提供远程指令执行或音频流。蓝牙初始化失败
仍可使用 USB，不以擦除 NVS 的方式修复初始化。

原有 USB 启动方式及依赖保持不变，蓝牙可选环境：

```sh
python3 -m venv runtime/ble-venv
runtime/ble-venv/bin/python -m pip install -r tools/buddy/requirements-ble.txt
runtime/ble-venv/bin/python tools/buddy/bridge.py --transport ble
# 多个设备时追加 --ble-address <地址或 macOS 外设 UUID>
```

在 macOS 设置中允许启动程序使用蓝牙。桥接按服务 UUID 查找设备，同一电脑
只运行一个蓝牙桥接；USB 桥接可同时运行，其有效心跳会保持优先权。
仅插 USB 供电不会抢占连接，必须收到有效状态包。无线使用仍需给设备供电。
可选客户端固定 Bleak 0.22.3 以兼容 Python 3.9；USB 不导入该依赖。

## 0.4.5 — PCM 音量控制

用户观察到百分比变化但声音大小不变。原应用只设置音频芯片音量，没有 PCM
增益环节；BSP 的无返回值设置接口无法报告写入失败，硬件层具体原因尚未确认。
现在将芯片音量固定在参考值 50，把屏幕 0–100% 直接应用到有符号 16-bit PCM。
默认 25% 比参考值衰减约 12 dB，按芯片默认曲线接近之前的默认音量。
每个 256 采样块在 16 ms 内平滑到目标值；播放中静音会平滑降至零。
保留原有按键操作与 96 ms 排空尾部。

主机回归覆盖采样能量单调变化、满幅正负值边界、零音量/静音、增益平滑以及
真实情绪短音在 25/50/100% 下的幅度变化。这些不代表喇叭响度或实体按键验证。

## 按键和状态

- UP/DOWN：切换任务详情。OK：待命或完成时挥手。
- 长按 OK：进入 20 种状态动画预览。UP/DOWN 翻页，OK 返回。
- 预览明确显示 DEMO，真实任务状态会打断预览。
- 空闲 90 秒降至 15% 亮度，任意键仅唤醒，不执行其他操作。
- USB 心跳中断 15 秒显示断开。等待和错误不会自动消失。
  只有真实的任务结束事件才显示完成。

## 电脑桥接

使用安装了 pyserial 的 Python 环境运行：

```sh
python tools/buddy/bridge.py --port /dev/cu.usbmodem3101
```

桥接读取本机 `~/.codex/sessions` 近期 JSONL 元数据，仅通过 USB 传递状态、
英文项目目录名、并行任务数、用时及序号，不传递提问、回答、工具输出。
USB 为 115200 波特率、版本 1 JSON 行，每个有效数据包回复 `buddy_ack`。
`--dry-run` 可查看状态而不连接设备；`--project ai-passport` 可限定项目。
停止进程会释放 USB，拔插后自动重连。不安装全局开机启动。

这是基于本机记录文件的桌面伴侣，文件格式未来可能变化。
已知工具按操作归类，其他活动统一显示工作中。
支持“等待审批”的显示和通信状态，但不会从命令文字猜测真实审批事件。
桥接扫描 UTC 今天及昨天，忽略一小时无活动的任务，因此不能确认更早或
遗留任务的实际状态。设备不会代替用户批准或执行电脑操作，无需 API Key。

## 3D 与音效（0.2.0）

机器人使用实时透视投影、背面剔除、深度排序和分面明暗；转头、摆动、打字、庆祝与休眠姿态由原有状态驱动，目标更新率 10 FPS，不使用大幅序列帧。任务相关道具继续使用轻量二维提示。

开机、按键、收到任务、完成、等待/确认和出错播放短促方波音效（16 kHz / 16-bit PCM 合成，5 ms 淡入淡出，输出音量 25%）。工作状态切换与重复心跳静音。长按 UP 切换静音，底栏显示 SFX OFF；重启默认开启，不写入 Flash。音频由独立任务播放，单槽队列合并积压，不阻塞按键回调或显示；故障只禁用音频。静音不代表硬件断电。

新增主机测试验证音频幅度、时长、尾部静音和 20 状态共 10,000 帧的投影边界及排序。构建与模拟不能证明实机帧率、视觉效果或扬声器听感，这些仍需实机确认。

## 音量与宠物表情（0.3.0）

长按 DOWN 进入/退出音量调节：短按 UP/DOWN 每次加/减 5%，范围 0–100%，OK 退出，10 秒无操作自动退出；百分比和刻度显示在现有底栏。调节到非零音量会短音试听，0% 无声。长按 UP 保留静音/恢复，静音不丢失原音量；从静音状态按音量加减会恢复声音。音量仅当前开机有效，重启默认 25%，不写 Flash。所有 codec 操作仍由音频任务单独负责；主线程只提交请求。

参考 EMO 官方展示的眼神表达方式（https://living.ai/emo/），自行绘制放大的黑色面屏与青蓝发光眼睛，保留原有 3D 身体与 20 个任务状态。待机眨眼/张望、思考大小眼、阅读向下看、工作眯眼、完成笑眼、错误叉眼、取消垂眼、休眠闭眼均为程序生成，不使用官方动画素材。

主机测试新增音量限幅、极值输入、静音恢复、状态表情映射、眨眼与 10,000 帧的模型边界检查。本次固件是否烧录及实机结果以交付记录为准；预览动画不是实机录像。
